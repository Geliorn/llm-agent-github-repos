# Pinterest-картинки репозиториев

Версия плагина 0.9.0, 2026-10-14. Для каждого репозитория собирается картинка 1000×1500 (2:3, формат Pinterest). Импорт в Pinterest делает **отдельный плагин** — этот только собирает картинку и отдаёт её через мета и хук.

## Что на картинке

Сверху вниз: автор → название репозитория → плашки ★ stars и forks → полоса языков с легендой («TypeScript 71% · Python 22% · …», цвета как на GitHub) → три блока: «Что это?», «Что это делает?», «Какую проблему решает?» → подвал (домен сайта). Аватара нет, только текст — решение 2026-10-14.

## Откуда данные

| Что | Источник |
|---|---|
| автор, название | `_gh_owner_login`, `_gh_full_name` |
| stars, forks | `_gh_stars`, `_gh_forks` (12.5k или 12 500 — настройка пресета) |
| языки | `_gh_languages_json`; если пусто — один запрос к GitHub `/languages`, результат сохраняется; если и его нет — основной язык 100% |
| тексты трёх блоков | `_gh_pin_texts` — при сборе пишутся моделью **в том же запросе**, что и описание (поля `pin_what` / `pin_does` / `pin_problem`); для старых записей — отдельный короткий запрос по сохранённому описанию; можно править вручную в метабоксе |

Лимит символов на блок, который получает модель, не угадан, а **измерен** на раскладке пресета по умолчанию, по среднему кеглю (`LAGR_Pin_Composer::block_budget()`).

## Текст не обрезается

Правило перенесено из инфографики `llm-agent-articles`: у трёх блоков один кегль, он подбирается по самому длинному и опускается до минимума. Если блок не влезает и так, модель переписывает его короче под измеренный бюджет (до двух проходов). Если не влезло и после этого — картинка **не собирается**, причина пишется в журнал и в метабокс. Отбрасывать нечего: блоков ровно три.

Длинное имя репозитория переносится по `-`, `_`, `.`, `/` и тоже не обрезается: если не влезло в заданное число строк на минимальном кегле — занимает ещё одну строку.

## Когда собирается

- при сборе нового репозитория (переключатель на экране «Pinterest-картинки», по умолчанию включён);
- кнопкой в метабоксе на экране репозитория («Собрать картинку», «Новые тексты»), действием «Собрать pin» в строке списка и массовым действием «Собрать Pinterest-картинки» (до 20 за раз);
- `wp github-repos pin <id>...`, `--all`, `--missing`, `--preset=<id>`, `--retext`, `--limit=<n>`.

Пересборка удаляет предыдущую картинку этого репозитория: у репозитория всегда одна актуальная картинка.

## Контракт для Pinterest-плагина

| Что | Где |
|---|---|
| id вложения с картинкой | post meta `_gh_pin_image_id` (int) |
| тексты трёх блоков | post meta `_gh_pin_texts` (array из 3 строк) |
| готовое описание пина | post meta `_gh_pin_description` — краткое описание + «owner/repo на site» |
| время сборки | post meta `_gh_pin_generated_at` (unix) |
| пресет | post meta `_gh_pin_preset` |
| ошибка последней сборки | post meta `_gh_pin_error` (пусто — ошибки нет) |
| событие | `do_action( 'lagr_pin_image_created', $post_id, $attachment_id, $info )`, где `$info` = `url`, `link` (страница репозитория), `title`, `description`, `texts` |

Мета зарегистрированы с `show_in_rest` (чтение — для пользователей с `edit_posts`). Alt у вложения — название и тексты блоков. Вложение помечено мета `_lagr_pin = 1`.

## Пресеты

Экран «GitHub-репозитории → Pinterest-картинки»: полный редактор пресетов с живым предпросмотром на реальном репозитории или образце. Три стартовых: «Тёмный (GitHub)», «Светлый», «Акцентный, с номерами». Настраиваются полотно и формат; фон (цвет, картинка из медиатеки, фильтры, тонирование, градиент, PNG-маска); шапка; плашки счётчиков; полоса и легенда языков; заголовки и раскладка блоков, плашки, маркеры, кегли; подвал с подстановками `{site}` `{repo}` `{owner}` `{url}`; логотип; рамка; отдельные шрифты для заголовков и текста.

Шрифты: загрузка TTF/OTF на том же экране (папка `uploads/lagr-fonts`); подхватываются и шрифты, загруженные для статей (`uploads/laa-fonts`). Без загруженных — системные: жирное начертание для заголовков, обычное для текста.

## Откуда код

Перенесён **копией** из `llm-agent-articles` (ветка `claude/gracious-einstein-69fzjs`), зависимости между плагинами нет:

| Здесь | Там |
|---|---|
| `LAGR_Image_Composer` | `LAA_Image_Composer` — конвейер фона, логотип, текст, сохранение (без раскладки подписи обложки) |
| `LAGR_Pin_Composer` | `LAA_Infographic_Composer` — подбор единого кегля, ячейки, маркеры; плюс своё: шапка, счётчики с векторными иконками, полоса языков |
| `LAGR_Pin_Presets` | `LAA_Infographic_Presets` — те же имена полей фона |
| `LAGR_Pin_Service` | `LAA_Infographic_Service` + `LAA_Title_Shortener` — переписывание вместо обрезки |
| `assets/js/lagr-pin.js` | `assets/js/laa-images.js` |

## Проверено

WordPress 6.8.3 (SQLite), подменённые GitHub API и LLM: все три пресета и длинное имя; переписывание переполненного блока моделью и сохранение итогового текста; размер вложения 1000×1500; кэширование языков; хук; пересборка с удалением старой картинки без повторных запросов к модели; понятная ошибка без LLM; сборка при работе правила с текстами из запроса описания. По HTTP: экран, предпросмотр (образец и реальный репозиторий с подменой текста), сохранение пресета, метабокс в блочном редакторе, ссылка сборки с выбором пресета, строковое действие; WP-CLI. Не проверено с живой моделью и на реальном сайте.
